## (а) Нормативный текст EN — SPEC.md, раздел «### 3.4 Logging»
(дописать в конец раздела, после блока I14; существующий текст не менять)

---EN BEGIN---
The memory-layer taxonomy below is a policy extension setting (see
`extensions.policy` in maqs-way-standard.json); it is not part of the
core data model (`schema_version way-v0.1.3`, frozen). It reuses the
existing canon: `scope_enum` (grouping boundary, data model), retention
(storage duration, §2.2), the `abstention_rate` metric
(verification_suite) — referenced, never duplicated. The
per-record/per-query `layer` is a profile extension field (see
`extensions.fields` in maqs-way-standard.json; values `persistent` |
`session` | `transient`; not required — absence means `unknown`).

**I15 — Layer taxonomy ([REC], MAQS I15).** Diagnose → layer →
interpret; never interpret without a layer. The layer enum is exactly
{`persistent`, `session`, `transient`} (closed; cardinality 3, owner:
I15; extension only by a new owner decision): `persistent` — long-lived
memory store (§2.1 records); `session` — current conversation context;
`transient` — ephemeral, no persistence guarantee. `unknown` is NOT a
fourth layer — it is an honest diagnostic state (unclassifiable input is
a fact).

**I15 — Layer assignment (declared, not inferred).** Layer is a DECLARED
property of the query/record (metadata set at creation by the request
creator). `identify(query)` READS the declared layer; it does NOT infer
it. Inferring a layer ("looks like session") is a label without source →
RED. No declaration → `unknown`, never a guess. Silent default
substitution (a quiet `session` for undeclared input) is a level
substitution — silent-fail class (B5-family).

**I15 — Expectations by layer (bound to the DECLARED layer, before
interpretation).** `persistent`: verbatim recall expected; deviation is
a degradation signal. `session`: noise/imperfection within one session
is expected behavior, NOT degradation; do not raise alerts on
session-scoped drift. `transient`: an exact answer is a bonus, never
evidence — accuracy of a transient layer cannot certify memory health
(absence-of-guarantee is not presence-of-guarantee). Invariant: applying
one layer's expectations to another layer's answer is a reading error
(false RED / false GREEN alike).

**I15 — Unknown handling (fail-closed and loud).** `unknown` → suspend
judgment: NO degradation verdict AND NO success verdict (abstention,
counted toward the existing `abstention_rate` metric); conservative mode
+ explicit loud diagnostic event (LOG-3.4), non-blocking ([REC]
advisory verdict model, cf. I14). The layer MUST NOT be guessed to
unblock interpretation.

**I15 — Orthogonality (three axes, no dual ownership).** `layer` =
lifetime CLASS (named enum above) — interpretation axis; `scope` =
grouping BOUNDARY (`scope_enum`) — pool/ownership axis; `retention` =
storage DURATION (parameter, §2.2) — time axis. Layer is a read-only
diagnostic label: it owns no storage and sets no policy. Anti-confusion:
scope "local-session" (access boundary) ≠ layer "session" (source
context); layer `transient` vs short retention are both "about short" —
divorced by kind (named class vs number); a class is never derived from
a duration and vice versa. I15 references §2.2 where lifetime is
defined; it never duplicates canon. I15 declares no tunable numeric
parameters: the only number is the closed enum's cardinality (3,
owner: I15; change = new owner decision).

Deferred (v0.4 list): heuristic layer assignment with declared
confidence (source-backed inference; inference without source remains
RED); tumbling-window review of layer expectations; semantic adequacy
of expectations.

Glossary (frozen; redefinition only via separate sanction):
`layer` — declared lifetime class (persistent/session/transient);
`unknown` — honest diagnostic state, not a layer; `identify` — reads
the declared layer, never infers; `expectation` — answer-quality rule
bound to the DECLARED layer; `reading error` — applying one layer's
expectation to another layer's answer.
---EN END---

## (б) RU-зеркало — SPEC-RU.md, раздел «### 3.4 Логирование»
(дописать в конец раздела, после блока I14; существующий текст не менять)

---RU BEGIN---
Таксономия слоёв памяти ниже — настройка расширения политики (см.
`extensions.policy` в maqs-way-standard.json); она не входит в ядро
модели данных (`schema_version way-v0.1.3`, заморожена). Она
переиспользует существующий канон: `scope_enum` (граница группировки,
модель данных), retention (длительность хранения, §2.2), метрику
`abstention_rate` (verification_suite) — ссылки, а не дублирование.
Поле `layer` записи/запроса — поле расширения профиля (см.
`extensions.fields` в maqs-way-standard.json; значения `persistent` |
`session` | `transient`; не обязательно — отсутствие означает
`unknown`).

**I15 — Таксономия слоёв ([REC], MAQS I15).** Диагностика → слой →
интерпретация; никогда не интерпретировать без слоя. Перечень слоёв —
ровно {`persistent`, `session`, `transient`} (замкнутый; мощность 3,
owner: I15; расширение — только новым решением владельца): `persistent`
— долговременное хранилище памяти (записи §2.1); `session` — текущий
контекст разговора; `transient` — эфемерный, без гарантий
сохранения. `unknown` — НЕ четвёртый слой, а честное диагностическое
состояние (неклассифицируемый ввод — это факт).

**I15 — Назначение слоя (декларируется, не выводится).** Слой —
ДЕКЛАРИРУЕМОЕ свойство запроса/записи (метаданные, выставляемые при
создании автором запроса). `identify(query)` ЧИТАЕТ объявленный слой;
он его НЕ выводит. Вывод слоя («похоже на session») — метка без
источника → RED. Нет объявления → `unknown`, никогда не догадка.
Молчаливая подстановка умолчания (тихий `session` для необъявленного
ввода) — подмена уровня, silent-fail класс (семейство B5).

**I15 — Ожидания по слоям (привязаны к ДЕКЛАРИРОВАННОМУ слою, до
интерпретации).** `persistent`: ожидается дословное воспоминание;
отклонение — сигнал деградации. `session`: шум/несовершенство внутри
одной сессии — ожидаемое поведение, НЕ деградация; не поднимать алерты
по session-дрейфу. `transient`: точный ответ — бонус, никогда не
доказательство — точность transient-слоя не может сертифицировать
здоровье памяти (отсутствие гарантии не есть наличие гарантии).
Инвариант: применение ожиданий одного слоя к ответу другого слоя —
ошибка чтения (как ложный RED, так и ложный GREEN).

**I15 — Обработка unknown (fail-closed и громко).** `unknown` →
приостановить вынесение суждения: НИ вердикта деградации, НИ вердикта
успеха (абстиенция, засчитывается в существующую метрику
`abstention_rate`); консервативный режим + явное громкое
диагностическое событие (LOG-3.4), не блокирующее (advisory-модель
вердикта [REC], ср. I14). Слой ОБЯЗАН НЕ угадываться ради разблокировки
интерпретации.

**I15 — Ортогональность (три оси, без двойного владения).** `layer` —
КЛАСС времени жизни (именованный перечень выше) — ось интерпретации;
`scope` — граница ГРУППИРОВКИ (`scope_enum`) — ось пула/владения;
`retention` — длительность ХРАНЕНИЯ (параметр, §2.2) — временная ось.
Слой — read-only диагностическая метка: не владеет хранилищем и не
задаёт политику. Анти-смешение: scope «local-session» (граница доступа)
≠ слой «session» (контекст источника); слой `transient` и короткий
retention оба «про короткое» — разведены по роду (именованный класс vs
число); класс никогда не выводится из длительности и наоборот. I15
ссылается на §2.2, где определено время жизни, и никогда не
дублирует канон. I15 не объявляет настраиваемых числовых параметров:
единственное число — мощность замкнутого перечня (3, owner: I15;
изменение = новое решение владельца).

Отложено (список v0.4): эвристическое назначение слоя с объявленной
уверенностью (вывод с источником; вывод без источника остаётся RED);
tumbling-ревизия ожиданий по слоям; семантическая адекватность
ожиданий.

Глоссарий (заморожен; переопределение — только отдельной санкцией):
`layer` — объявленный класс времени жизни (persistent/session/
transient); `unknown` — честное диагностическое состояние, не слой;
`identify` — читает объявленный слой, никогда не выводит;
`expectation` — правило качества ответа, привязанное к
ДЕКЛАРИРОВАННОМУ слою; `reading error` — применение ожиданий одного
слоя к ответу другого слоя.
---RU END---
