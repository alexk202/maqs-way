## (а) Нормативный текст EN — SPEC.md, раздел «### 3.2 Measurable
Quality — indicative targets» (дописать в конец раздела, после
примечаний; существующий текст не менять)

---EN BEGIN---
The pipeline-hygiene rules below are policy extension settings (see
`extensions.policy` in maqs-way-standard.json); they are not part of the
core data model (`schema_version way-v0.1.3`, frozen). They discipline
the verification apparatus tabulated in this section: the CI gates and
the counters those gates report.

**0.5a — Dead code ([CRIT], MAQS 0.5a).** Green tests on code never
invoked by the running system are a false safety signal. Rule: every
verification script MUST be either (a) invoked from the audit CLI
(`maqs_way_audit.py`), or (b) listed in the declared-standalone list
with a documented integration point. Uninvoked AND undocumented = dead →
RED. The declared-standalone list is closed: extension happens by
explicit change (commit) only, never silently. Self-hosting applies:
the hygiene gate scans its own repository, including itself — an
unwired and unpointed gate flags itself. A check that cannot fail is
not a check. 0.5a declares no numeric parameters.

**0.6a — Local baselines ([IMP], MAQS 0.6a).** Anomalies are defined
relative to the system's own baseline, not universal numbers. The
baseline file records namespaced counters with provenance (recording
commit + date). Declared tolerance: `tolerance` — default 0.10 (±10%)
per counter (owner: 0.6a); tolerance changes are declared and
owner-signed. Drift beyond tolerance → FLAG (advisory, visible,
accumulated), not RED: no canon threshold exists, and RED-on-growth
would punish legitimate work. RED only for: baseline missing or corrupt,
or a counter removed from tracking without explanation. The baseline
changes only with the commit that explains the drift.

Deferred (v0.4 list): 0.5a — invoked-but-unsatisfiable control (a
production call site is not enough; the control must be able to fire
under production configuration); golden canary corpus for P9; auditor
certification checklist; canonical drift tolerances per store;
aggregating standalone gates into the audit CLI.

Glossary (frozen; redefinition only via separate sanction):
`declared-standalone` — a verification script not wired into the audit
CLI but listed with a documented integration point; `self-hosting` —
the hygiene gate scans its own repository including itself; `baseline`
— recorded namespaced counters with provenance; `tolerance` — declared
drift bound per counter (default ±10%); `FLAG` — advisory drift
report, not a verdict.
---EN END---

## (б) RU-зеркало — SPEC-RU.md, раздел «### 3.2 Измеримое качество —
ориентировочные цели» (дописать в конец раздела, после примечаний;
существующий текст не менять)

---RU BEGIN---
Правила гигиены пайплайна ниже — настройки расширения политики (см.
`extensions.policy` в maqs-way-standard.json); они не входят в ядро
модели данных (`schema_version way-v0.1.3`, заморожена). Они
дисциплинируют верификационный аппарат, сведённый в таблицу этого
раздела: CI-гейты и счётчики, которые эти гейты отчечат.

**0.5a — Мёртвый код ([CRIT], MAQS 0.5a).** Зелёные тесты на коде,
который никогда не вызывается работающей системой, — ложный сигнал
безопасности. Правило: каждый верификационный скрипт ОБЯЗАН быть либо
(а) вызван из audit CLI (`maqs_way_audit.py`), либо (б) внесён в список
declared-standalone с задокументированной точкой интеграции.
Невызванный И незадокументированный = мёртвый → RED. Список
declared-standalone замкнут: расширение — только явным изменением
(коммитом), никогда молча. Самоприменимость: гейт гигиены сканирует
собственный репозиторий, включая себя — невключённый и без точки
гейт помечает сам себя. Проверка, которая не может упасть, — не
проверка. 0.5a не объявляет числовых параметров.

**0.6a — Локальные базлайны ([IMP], MAQS 0.6a).** Аномалии определяются
относительно собственного базлайна системы, а не универсальных чисел.
Файл базлайна хранит именованные счётчики с провенансом (коммит и дата
снятия). Объявленный допуск: `tolerance` — умолчание 0.10 (±10%) на
счётчик (owner: 0.6a); изменения допуска объявляются и подписываются
владельцем. Дрейф за пределом допуска → FLAG (advisory, видимый,
накопительный), не RED: канонического порога не существует, а
RED-при-росте наказывал бы легитимную работу. RED только для: базлайн
отсутствует или повреждён, либо счётчик снят с отслеживания без
объяснения. Базлайн меняется только тем коммитом, который объясняет
дрейф.

Отложено (список v0.4): 0.5a — вызванный-но-неудовлетворимый контроль
(производственная точка вызова — недостаточно; контроль должен уметь
сработать при производственной конфигурации); золотой корпус канареек
для P9; чек-лист сертификации аудитора; канонические допуски дрейфа по
хранилищам; агрегация standalone-гейтов в audit CLI.

Глоссарий (заморожен; переопределение — только отдельной санкцией):
`declared-standalone` — верификационный скрипт, не включённый в audit
CLI, но внесённый в список с задокументированной точкой интеграции;
`self-hosting` — гейт гигиены сканирует собственный репозиторий,
включая себя; `базлайн` — записанные именованные счётчики с
провенансом; `tolerance` — объявленная граница дрейфа на счётчик
(умолчание ±10%); `FLAG` — advisory-отчёт о дрейфе, не вердикт.
---RU END---
