---EN BEGIN---
The audit-procedure requirements below are policy extension settings
(see `extensions.policy` in maqs-way-standard.json); they are not part
of the core data model (`schema_version way-v0.1.3`, frozen). No new
data-model fields are introduced.

**P9 — Controlled artifact experiment (one-sided; MAQS §2, Step P9).**
When artifact–memory contamination is suspected: prepare a new artifact
of a different type, verify its syntax independently before delivery,
deliver it without prior disclosure, and record the result; a clean
read constitutes acceptance of the delivery channel. Diagnostic triad
P9-a / P9-b / P9-c: `canary` — unique data embedded mid-body, absent
from all memory stores; reproduced in the report = proof of reading;
absent = inconclusive. `decoy` — a plausible but false element that
memory would expect; any mention = proof of confabulation. `echo` — a
memory-true element absent from the artifact, thematically tempting;
appearing = proof of supplementation (E12 violation); absent =
inconclusive. All three probes are ONE-SIDED: a positive result is
PROOF of the tested property; a negative result is INCONCLUSIVE —
never pass, never "clean", only "not tested by this run". A silent
canary proves nothing about the threat — only about the canary. The
combined grid gives diagnosis; a single probe gives only
proof-or-silence. Every P9 run reports the line "negative =
inconclusive; coverage NOT claimed" — one-sidedness is declared
upfront, never implied. Mixing a one-sided run with a coverage claim is
RED (level substitution: "not detected" issued as "clean").

**P10 — External auditor isolation (read-only, verified by fact; MAQS
§2, Step P10).** Any automated or agent-driven audit runs from an
environment that has NO write-access to production stores and shares NO
runtime state (processes, caches, loaded embedding models) with the
audited system; audit results are written only to an external report.
Read-only is a DECLARED property, confirmed by fact, not by promise.
Procedure: snapshot the tree → run the gates → verify identical.
Verification MUST include untracked files (`git status --porcelain`,
not tracked-only): creating a new file IS a write even if tracked
files are untouched — otherwise false-safe. An audit step that writes
into the audited tree (modification OR new file) FAILS P10. Write
access for the auditor is out of scope (MAQS SUPP-EXT-01) — a declared
boundary, not a defect.

P9/P10 declare no tunable numeric parameters: their parameters are
structural (probe outcomes, snapshot equality).

Deferred (v0.4 list): P10 — lazy-initialization write paths (`mode=ro`
alone is not isolation); P11 — agent audit discipline.

Glossary (frozen; redefinition only via separate sanction):
`one-sided` — evaluation where a positive result = proof and a negative
result = inconclusive (never pass); `canary`/`decoy`/`echo` — the
P9-a/b/c probes; `coverage NOT claimed` — mandatory report line of
every one-sided run; `snapshot-run-verify` — the P10 procedure:
snapshot (including untracked files) → run the gates → verify
identical.

---RU BEGIN---
Требования процедуры аудита ниже — настройки расширения политики (см.
`extensions.policy` в maqs-way-standard.json); они не входят в ядро
модели данных (`schema_version way-v0.1.3`, заморожена). Новых полей
модели данных не вводится.

**P9 — Контролируемый артефактный эксперимент (односторонний; MAQS §2,
шаг P9).** При подозрении на заражение «артефакт–память»: подготовить
новый артефакт другого типа, независимо проверить его синтаксис до
вручения, вручить без предварительного раскрытия и зафиксировать
результат; чистое прочтение означает принятие канала доставки.
Диагностическая триада P9-a / P9-b / P9-c: `canary` — уникальные
данные, встроенные в середину тела и отсутствующие во всех хранилищах
памяти; воспроизведены в отчёте = доказательство чтения; отсутствуют =
неопределённо. `decoy` — правдоподобный, но ложный элемент, который
память ожидала бы; любое упоминание = доказательство конфабуляции.
`echo` — верный памяти элемент, отсутствующий в артефакте и тематически
соблазнительный; появление = доказательство дополнения (нарушение E12);
отсутствует = неопределённо. Все три пробы ОДНОСТОРОННИЕ: положительный
результат — ДОКАЗАТЕЛЬСТВО проверяемого свойства; отрицательный —
НЕОПРЕДЕЛЁННЫЙ — никогда не «пройдено», никогда не «чисто», только «не
проверено этим прогоном». Молчаливая канарейка не доказывает ничего об
угрозе — только о канарейке. Комбинированная сетка даёт диагноз;
одиночная проба даёт только «доказательство-или-тишину». Каждый прогон
P9 включает строку отчёта «negative = inconclusive; coverage NOT
claimed» — односторонность объявляется заранее, а не подразумевается.
Смешивание одностороннего прогона с заявкой на покрытие = RED (подмена
уровня: «не обнаружено», выданное за «чисто»).

**P10 — Изоляция внешнего аудитора (read-only, верифицируется фактом;
MAQS §2, шаг P10).** Любой автоматизированный или агентный аудит
выполняется из среды без права записи в продовые хранилища и без
общего рантайм-состояния (процессы, кэши, загруженные модели
эмбеддингов) с аудируемой системой; результаты аудита пишутся только во
внешний отчёт. Read-only — ДЕКЛАРИРУЕМОЕ свойство, подтверждаемое
фактом, а не обещанием. Процедура: снять снимок дерева → прогнать
гейты → убедиться в идентичности. Верификация ОБЯЗАНА включать
невнесённые файлы (`git status --porcelain`, а не только
отслеживаемые): создание нового файла ЕСТЬ запись, даже если
отслеживаемые файлы не тронуты — иначе ложная безопасность. Шаг
аудита, пишущий в аудируемое дерево (модификация ИЛИ новый файл),
ПРОВАЛИВАЕТ P10. Право записи для аудитора вне объёма (MAQS SUPP-EXT-01) —
объявленная граница, а не дефект.

P9/P10 не объявляют настраиваемых числовых параметров: их параметры —
структурные (исходы проб, равенство снимков).

Отложено (список v0.4): P10 — пути записи с ленивой инициализацией
(`mode=ro` сам по себе не изоляция); P11 — дисциплина агентного
аудита.

Глоссарий (заморожен; переопределение — только отдельной санкцией):
`one-sided` (односторонний) — оценка, где положительный результат =
доказательство, а отрицательный = неопределённый (никогда не
«пройдено»); `canary`/`decoy`/`echo` — пробы P9-a/b/c;
`coverage NOT claimed` — обязательная строка отчёта каждого
одностороннего прогона; `snapshot-run-verify` — процедура P10: снимок
(включая невнесённые файлы) → прогон гейтов → проверка идентичности.
---RU END---
