## (а) Нормативный текст EN — SPEC.md, раздел «### 3.4 Logging»
(дописать в конец раздела, после блока I10/I11/I12; существующий текст
не менять)

---EN BEGIN---
Reaction requirements for probed exception classes below are policy
extension settings (see `extensions.policy` in maqs-way-standard.json);
they are not part of the core data model (`schema_version way-v0.1.3`,
frozen). The recipient vocabulary reuses the canon roles `owner` and
`operator`; no new data-model fields are introduced.

**I14 — Handler registry ([REC], MAQS I14).** If an exception class is
probed (caught and re-raised or logged) but has no registered handler or
escalation path, the probe is incomplete — detection without reaction is
not coverage. Every probed class MUST have a reaction: `handler` and/or
`escalation_path` (at least one). A `handler` is a local reaction on the
own-process side (halt-family, cf. I11); an `escalation_path` is
owner/operator notification with degraded continuation (external side,
escalate-family, cf. I12). A path MUST terminate at a declared recipient
(`owner` or `operator`); a path-into-void is uncovered — same class as
halt-without-alert (B5-family). Handler AND path simultaneously is
LEGAL (handler + fallback-path = defense in depth); forbidding the
combination is rejected. The dictionary is inherited from the class
counters (I10–I12), not redefined: halt : escalate :: handler : path;
counter classes listed in the registry carry reaction = counter
(aggregate / halt+alert / escalate) — defined by the counter canon,
referenced here, no double ownership.

**I14 — Declared catalog.** The class catalog is a DECLARED list;
completeness is NOT claimed and NOT gated. The report line "checked N
declared classes; completeness NOT claimed" is mandatory; N is derived
from the declared catalog (no independent default, owner: I14). Growth
happens by explicit change (commit) only, never silently at runtime;
each new class enters with a source (incident/audit) and an owner.

**I14 — Verdict model (two levels, not a choice).** Probe level (unit):
a catalog inconsistency is STRICT — orphan class (no reaction), dead
handler (registered for no catalog class), path-into-void → RED; a check
that cannot fail is not a check. Gate level (integration): [REC]
findings are reported-not-failing — the aggregate gate is not blocked,
but every finding MUST be NAMED in the report (never folded); [REC]
governs BLOCKING, not verdict-ability. "0 findings" and "check not run"
are distinguished states. Coverage ratio `handled/probed` is reported,
not gated (owner: I14); every orphan is listed by name. The [REC]
advisory status is carried in the REPORT, not in gate semantics. I14
declares no tunable numeric parameters: the counts above are derived,
reported values.

Deferred (v0.4 list): owners_registry / SLA / fallback schema for
escalation paths (no canon source for SLA scales); tumbling catalog
review; exception taxonomy import.

Glossary (frozen; redefinition only via separate sanction):
`handler` — local reaction on the own-process side; `escalation_path` —
owner/operator notification with degraded continuation, terminating at a
declared recipient; `orphan class` — probed class with no registered
reaction; `dead handler` — registered handler with no catalog class;
`path-into-void` — escalation path whose target is not a declared
recipient; `handled/probed` — coverage ratio, reported not gated.
---EN END---

## (б) RU-зеркало — SPEC-RU.md, раздел «### 3.4 Логирование»

---RU BEGIN---
Требования к реакции для проверенных исключений ниже —
настройки расширения политики (см. `extensions.policy` в
maqs-way-standard.json); они не входят в ядро модели данных
(`schema_version way-v0.1.3`, заморожена). Словарь получателей
переиспользует канонические роли `owner` и `operator`; новых полей
модели данных не вводится.

**I14 — Реестр обработчиков ([REC], MAQS I14).** Если класс исключения
проверен (пойман и перевыброшен или залогирован), но не имеет
зарегистрированного обработчика или пути эскалации, проверка
неполна — обнаружение без реакции не является покрытием. Каждый
проверенный класс ОБЯЗАН иметь реакцию: `handler` и/или
`escalation_path` (минимум одно). `handler` — локальная реакция на
стороне собственного процесса (семейство halt, ср. I11);
`escalation_path` — уведомление владельца/оператора с продолжением в
деградировавшем режиме (внешняя сторона, семейство escalate, ср. I12).
Путь ОБЯЗАН завершаться в объявленном получателе (`owner` или
`operator`); путь-в-пустоту не покрыт — тот же класс, что
halt-без-alert (семейство B5). Handler И path одновременно — ЛЕГАЛЬНО
(handler + запасной path = эшелонированная защита); запрещать
сочетание отвергается. Словарь наследуется от классовых счётчиков
(I10–I12), не переопределяется: halt : escalate :: handler : path;
классы-счётчики, внесённые в реестр, несут reaction = counter
(aggregate / halt+alert / escalate) — определены каноном счётчиков,
здесь упоминаются, двойного владения нет.

**I14 — Объявленный каталог.** Каталог классов — ОБЪЯВЛЕННЫЙ список;
полнота НЕ заявляется и НЕ гейтируется. Строка отчёта «checked N
declared classes; completeness NOT claimed» обязательна; N выводится из
объявленного каталога (без независимого умолчания, owner: I14). Рост —
только явным изменением (коммитом), никогда молча в рантайме; каждый
новый класс входит с источником (инцидент/аудит) и владельцем.

**I14 — Модель вердикта (два уровня, не выбор).** Уровень пробы
(юнит): несогласованность внутри каталога — СТРОГО — класс-сирота (нет
реакции), мёртвый обработчик (зарегистрирован без класса каталога),
путь-в-пустоту → RED; проверка, которая не может упасть, — не
проверка. Уровень гейта (интеграция): находки [REC] —
report-not-failing — агрегатный гейт не блокируется, но каждая находка
ОБЯЗАНА быть НАЗВАНА в отчёте (никогда не сворачивается); [REC]
управляет БЛОКИРОВАНИЕМ, а не вердиктоспособностью. «0 находок» и
«проверка не запускалась» — различимые состояния. Доля покрытия
`handled/probed` — отчёт, не гейт (owner: I14); каждая сирота
перечисляется по имени. Статус [REC] (advisory) переносится в ОТЧЁТЕ,
а не в семантике гейта. I14 не объявляет настраиваемых числовых
параметров: указанные выше числа — производные, отчётные значения.

Отложено (список v0.4): owners_registry / SLA / fallback-схема для
путей эскалации (нет канонического источника шкал SLA); ревизия
каталога tumbling; импорт таксономии исключений.

Глоссарий (заморожен; переопределение — только отдельной санкцией):
`handler` — локальная реакция на стороне собственного процесса;
`escalation_path` — уведомление владельца/оператора с продолжением в
деградировавшем режиме, завершающееся в объявленном получателе;
`orphan class` — проверенный класс без зарегистрированной реакции;
`dead handler` — зарегистрированный обработчик без класса каталога;
`path-into-void` — путь эскалации, чей адресат не является объявленным
получателем; `handled/probed` — доля покрытия, отчёт, не гейт.
---RU END---
