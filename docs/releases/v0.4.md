# MAQS-Way v0.4 — sync and specification release

Date: 2026-11-18. Non-prerelease. Tag on the owner-signed canon commit.

## Canon

Two things close in this release: the formulations carried over from the
two MAQS syncs, and the four deferrals Way left open at v0.3. The core
reference moves to MAQS v1.10 (released 2026-11-18, tag `v1.10`, commit
`c9253e2`, 99 items). `schema_version way-v0.1.3` — FROZEN (data model
unchanged, asserted fact); release stamps bumped (SPEC/RU v0.4;
JSON / spec-manifest / scoreboard / CITATION.cff 0.4.0, 2026-11-18).
Open known gaps: the v0.5 list in SPEC §6, reproduced below.

The canon text was prepared for signature before application, as pairs of
exact replacements with anchors taken verbatim from the canon:
`docs/v0.4-canon/maqs-sync-1.8.1-1.9.md` (24 pairs),
`docs/v0.4-canon/way-deferred-specs.md` (10 pairs),
`docs/v0.4-canon/maqs-core-ref-1.10.md` (11 version mentions plus the
single source). Application was mechanical and reproduced byte-for-byte
by a second party before the signature was given.

## Way's own deferrals — closed

- `deletion_marker` — resolved by separation: a live record carries no
  such field; the marker exists only as the separate artifact governed by
  `schemas/deletion-marker.schema.json`. No core field added.
- `identity_signature` — specified: Ed25519 over the JCS RFC 8785
  canonical serialization of the signed view; field format
  `ed25519:<base64url-signature>:<key_id>`; verification fails closed on
  an unknown key, a missing field or a canonicalization error. Scope of
  the claim stated in the canon: tamper-evidence for a record at rest,
  not proof of content truth nor of the human behind the writing agent.
  The JSON `canonicalization_for_signature.status` moves from deferred
  to defined.
- `operator` — full permission matrix with deny-by-default; deletion is
  denied to the operator and runs through the lifecycle; every allowed
  action appends provenance, and its absence is a policy violation, not a
  logging gap.
- `knowledge_update` — mirrored into JSON `verification_suite.metrics`
  exactly as the §3.2 table reads: target 0.7, no CI gate declared,
  indicative until a first real-system run.

## Deferred lists — all five revised

The canon carried five "Deferred (v0.4 list)" lines, not one. Each was
resolved explicitly; silence would have been a silent rollover.

- §3.2 — the 0.5a entry closes; golden canary corpus, auditor
  certification checklist, canonical drift tolerances and audit-CLI
  aggregation retarget to v0.5.
- §3.4 counters — retargets whole: per-scope/per-subject partitioning
  must agree with E10 cap semantics, which is a design decision rather
  than a wording sync.
- §3.4 handlers — retargets whole: no canon source for SLA scales, and
  inventing one in a sync release is not allowed.
- §3.4 layers — retargets whole: relaxing "inference without source
  remains RED" is a design decision carrying risk.
- §3.5 — closes whole (P10 lazy initialization, P11).

## Gate tooling fixed in this release

Two defects in the gates themselves, both found before the release, both
non-canon:

- G0's stale-stamp list carried the bare numeric previous version, which
  collided with the §1 P8 threshold `<0.3` and would have demanded
  falsifying a threshold; the three stamp-form tokens were built with a
  doubled "v" and had never matched anything. Markers are now the display
  form, the `standard_version` report form and the full stamp (`ee0d584`).
- The `--self-test` shapes were pinned to one canon state: the G8 needle
  named MAQS v1.9 verbatim, and G0 shape 1 asserted "the released v0.3
  verdict". Both now derive from the canon — the needle from
  `maqs_core_reference`, the stamp from the SPEC H1 — so a future core
  reference or release cannot break the self-test.

## Open known gaps — target v0.5

D8 pinned axes and D10 similarity computation contract (no Way coverage
gate); normative thresholds for the §3.2 metrics (await a first
real-system run); executable behavioral harness (LoCoMo/LongMemEval) and

Nothing in this list is claimed as closed anywhere in the canon.

## Rollback before the tag (recorded, not hidden)

The canon was applied once, on 2026-11-18, and signed. Before the tag was
cut, the release gate run at the NEXT target found three wording defects in
that text: a historical reference naming the previous version inside canon
prose (§2.1), a version named in prose where it carried no stamp (which
would have handed the next release a twenty-line sweep), and a §7 claim of
completeness that was false — the canon held six references to a deferred
v0.4 list, not five, and the sixth was unresolved. The canon commit was
unreleased and untagged, so it was rolled back and the prepared text was
corrected before application. The release therefore carries one signature
over text that is correct as written, not corrected afterwards.
