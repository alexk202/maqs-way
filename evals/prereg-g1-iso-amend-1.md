# Amend-1 к prereg-g1-iso (решение владельца по СТОПу g1-iso-a, 2026-10-25)

Status: содержание задано решением владельца от 2026-10-25 (ответ на СТОП по §1);
коммит до запуска; supersedes указанные пункты базового `prereg-g1-iso.md`,

## 0. Контекст

СТОП g1-iso-a показал: редирект per-RUN (одна temp-history на прогон) сохранял
внутрипрогонный скользящий хвост (16.5% чужих фактов — тот же механизм, что у
замороженного g1; физика и внутренний контроль q0=0 — `results/g1iso_a_note.md`).
Прогон g1-iso-a переименован и используется как **replicate of frozen g1** —
второй замер той же конфигурации (таблица межпрогонного разброса классов — в
заметке; главное: capped ×3.5, loop ×3, links +50% при стабильных R@5/total —
одиночные пороги этих классов не интерпретируемы без полос по повторам).

## 1. Гранулярность изоляции — PER QUESTION (supersedes §0 базового)

Дельта к замороженному g1 по-прежнему ровно одна — `history_db_path` — теперь
**per-question**: `"history_db_path": temp_history_db(f"{STORE}/q{qi}")` в cfg
каждого вопроса → `get_last_messages` ПУСТ для каждого extraction-вызова.
Изоляция per-question вводится во ВСЕХ раннерах (не только g1-iso-b) — раскрытие
в коммите; H5-гард без изменений. Раннер: `run_single156_g1iso_b.py` (копия
g1-раннера с per-question редиректом и переименованными выходами — замороженный
g1-эвиденс не перезаписывается): STORE `mem0single156g1iso_b_*`, артефакт
`pilot_evidence_single156_g1iso_b.json`, чекпоинт `single156_g1iso_b_partial.json`.

## 2. ПОРЯДОК меняется (supersedes §5 базового)

1. Гард selftest → OK.
2. Smoke `pilot_longmemeval_n5.py` (5 вопросов, гард GREEN, stand OK).
3. **СНАЧАЛА ЧАСТЬ B**: `run_g1iso_panel12.py` — панель-12 × 2 повтора, ~12 мин;
   гард и per-question изоляция активны; артефакт `g1iso_panel12_repro.json`.
4. **§1-проверка части B**: `g1iso_fix_check.py <panel-store>` — детектор чужих
   фактов на сторах ОБОИХ повторов (по каждому проходу; допуск тот же:
   confirmed ≤ 5 фактов в ≤ 5 вопросах, weak ≤ 20 на проход). Вне допуска → СТОП.
5. **Затем g1-iso-b**: `run_single156_g1iso_b.py`, ~1 ч.
6. **§1-проверка g1-iso-b**: `g1iso_fix_check.py <b-store>` — первичная, как в

7. `g1iso_verbatim_panel.py <b-store>` — §3.3 базового пререга (panel-mean против
   0.162, порог 0.03).
8. §2/§3 базового: таблица против замороженного g1, решения.

## 3. НОВОЕ ПРАВИЛО интерпретации (добавление к §2/§3 базового)

**Если часть B даёт расхождение повторов** (хотя бы один вопрос не
байт-идентичен между повтором 1 и повтором 2): сравнение классов g1-iso-b против
g1 **по одному прогону НЕ интерпретируется** (межпрогонная дисперсия классов,
показанная парой g1/g1-iso-a, делает одиночные пороги loop/capped/links
неосмысленными). Вместо этого — **предложение пакета «полосы по N повторам»
владельцу**: классовые метрики (capped, loop, links, total memories, композиция)
оцениваются полосами по N ≥ 3 повторам одной конфигурации; N и состав — на
решении владельца. R@5/empty/mal/trunc (стабильные в паре g1/g1-iso-a) в этом
правиле не участвуют и сравниваются как в базовом пререге.

Если часть B даёт полную байт-идентичность 12/12 — сравнение классов по одному
прогону g1-iso-b интерпретируется по базовым порогам §3 (при этом сама
идентичность повторов = довод в пользу «GPU-недетерминизм остаётся» против
гипотезы хвоста — по букве критерия §4 базового пререга).
