# Pre-reg-lite: зонд причины дрейфа панели-12 после full-500-iso (26.10)

ТЗ владельца; короткий зонд ~15–30 мин GPU. Формат — prereg-lite как у
реп-пенальти-зонда (`c9c0dba`): критерии записаны ДО запуска, коммит до
любых прогонов, выводы — append-only. Пререги прошлых пакетов не трогаются.

## Контекст

Ночной full-500-iso: панель-12 ПОСЛЕ против утреннего эталона 25.10 — **10/12**
(`full500iso_verdicts.md` finding 3). Сместившиеся вопросы:
- **311778f1** — 16 фактов (эталон: 21);
- **faba32e5** — 10 фактов (эталон: 5).
Оба выхода валидны; внутри окна ПОСЛЕ оба смещения воспроизводятся в паре
повторов (12/12) → состояние сервера после ~7 ч нагрузки детерминированно
смещает отдельные стабильные вопросы. Гипотезы: накопленное состояние
экземпляра (перезапуск снимает); носитель — кэш промптов (llama.cpp
cache_prompt; повторное использование KV даёт иную численную траекторию,
чем свежий расчёт предфильтра).

## Шаги и критерии (заранее)

**ШАГ A — свежий экземпляр сервера** (тот же build 9177, те же флаги, seed
42; панель-12 раннером `run_g1iso_panel12.py`, кэш промптов по умолчанию).
Сравнение: против утреннего эталона (`g1iso_panel12_repro_detA.json`) и
против панели ПОСЛЕ (`g1iso_panel12_repro_f500after.json`).
- **12/12 с эталоном → дрейф = накопленное состояние экземпляра**
  (перезапуск снимает); продолжаем к шагу B.
- Иначе (≤ 11/12 с эталоном) → причина не в состоянии экземпляра: записать,
  остановиться (выводы по данным, дальше не тянуть).

**ШАГ B — тот же свежий экземпляр**: 2 сместившихся вопроса (311778f1,
faba32e5), каждый дважды — с параметром запроса `cache_prompt=true` и
`cache_prompt=false` (через extra_body; полный extraction-поток g1-iso
конфига, свежий стор, per-question изоляция).
- **Выходы совпадают между режимами → на свежем сервере кэш численно
  нейтрален** (расхождение с шагом A невозможно → фиксируем и продолжаем к C
  для проверки под нагрузкой).
- Расхождение между режимами на свежем сервере → кэш НЕ нейтрален уже без
  нагрузки → сразу главный вывод (кэш промптов), шаг C — подтверждение.

**ШАГ C — воспроизведение нагрузки (лимит 20 мин)**: повторно отправить
первые ~100 extraction-запросов full-500-iso как префилл-нагрузку (из
артефакта прогона: чанкинг раннера + промпт-билдер mem0; приближение
раскрыто: existing_memories чанков 2+ берутся из записанных raw-выходов
прогона; генерация обрезана max_tokens=8 — для состояния кэша важен префилл;
запросы идут с кэшем по умолчанию). Затем 2 сместившихся вопроса дважды:
`cache_prompt=true` и `=false`.
Критерии (заранее):
- **true → смещённый вывод, false → эталонный → причина = кэш промптов**;
- оба эталонные → 100 запросов недостаточно, дрейф не воспроизведён —
  записать, не тянуть дальше;
- оба смещённые → причина в состоянии сервера помимо кэша.
