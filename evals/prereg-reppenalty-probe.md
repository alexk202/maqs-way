## 2. Критерии (захардкожены ДО чисел)

1. **Loop-критерий (главный):** существует P, при котором на ОБЕИХ loop-вопросах
   loop-фреймов 0 (facts < 2× unique) И unique ≥ 3 (экстракция жива) И mal = 0
   → «серверный рычаг существует» — кандидат линии В; обоснование loop-флага (ii):
   «лечение найдено, требует серверной дельты (отдельный пакет)».
   Ни один P не убил loop → «серверные рычаги исчерпаны» — обоснование loop-флага
   (ii): «лечения нет, флаг + эстафета Б».
2. **Name-критерий (риск-направление, по рецензии):** entity-recall при P>1.0
   относительно P=1.0-бейзлайна: падение при росте P → пенальти вредит именам
   (механизм подтверждён как риск; для (ii) держать 1.0, рычаг loop — только с
   контролем имен); плоскость/рост → пенальти нейтрален к именам, рычаг дёшев.
3. **Побочный гвард:** mal = 0 во всех вызовах; facts не коллапсирует (≥3 unique).
