# Amendment 1 — prereg-g1 (pre-run, по рецензии совета 24.10, Обсуждение_20)

К базовому пререгу: `evals/prereg-g1.md` (коммит `daf3886`).
Дата поправки: 2026-10-24. **До прогона, до любых чисел g1.** Гварды 1–2 и ядро
интерпретации базового пререга не отменяются — дополняются ниже. Правки по мотивам
рецензии совета (все пять рецензентов, Обсуждение_20): противоречие бюджета схемы,
непроверенный maxLength, недословный mal, асимметрия флагов состава, опечатка хеша,
эстафета (ii)→Б, хронология подписей.

## 1. Калибровка по факту (вместо оценки «40 ≈ 1850 токенов»)

Замерено 2026-10-24 (мем0-путь, конфиг g1, seed 42, T=0; 3 вопроса слайса:
`e982271f` b2-max-39 / `1903aded` средний / `75f70248` стеновой класс b4):
- **chars/token = 4.03–4.44** (812/199, 4996/1124, 1326/329; JSON-выдача на английском) —
  исходная оценка 3.9 была близка; страхи про кириллицу не подтвердились (датасет англ.);
- **длины фактов: 83–435 chars, среднее по пулу ≈ 190** (стандарт промпта mem0 —
  до ~700 chars, измеренный максимум 435);
- JSON-оверхед на факт ≈ 40 chars (id/кавычки/скобки).
- Честная оговорка: по-вопросные счётчики калибровки показали сильную вариативность
  (`e982271f`: 3 факта против 39 памятей в b2) — это НЕ метрика и НЕ вердикт;
  по-вопросные пересечения между прогонами не интерпретируются (канон §2 базового
  пререга); калибровка используется только для распределения длин и chars/token.

**Вывод бюджета (формула, все входы измеренные):**
`maxItems = floor(1800 токенов × 4.0 chars/токен ÷ (190 + 40)) = floor(31.3) = 31`,
где 1800 = 2000 × 0.9 (запас 10%). Диапазон совета (25–32) брондирует выведенное значение.
**maxItems: 40 → 31.** Хвосты выше p90 могут приближаться к стене — покрывается
оговоркой п.3 (capped/fr=length = флаг, не красный нейтральности).

## 2. Калибровка вскрыла новый класс: loop-паттерн под грамматикой

На `1903aded` модель под json_schema зациклилась: 16 фактов с циклически
повторяющимися длинами (112/435/235/230…), после дедупа mem0 сохранил 5. Грамматика
не порождает цикл, но и не мешает ему; итог — деградация состава памяти. Класс ловится
дёшево: фрейм, где `facts ≥ 2 × unique_texts` = loop-фрейм.

- **maxLength остаётся 900** (измеренный максимум 435, стандарт промпта ~700 → запас
  1.29×; снижение потолка режет легитимные детальные факты);
- **smoke C (кап 50, принудительный тест): maxLength ПРИНУЖДАЕТСЯ грамматикой** —
  факт обрезан ровно на 50 chars, JSON валиден, `fr=stop`. Подтверждён класс
  «trunc-field»: тихая обрезка поля, невидимая для mal=0 и trunc=0. Детектор:
  факты с длиной ровно 900 → флаг.

## 3. Что меняется (ровно семь пунктов)

1. **Схема**: `maxItems 40 → 31` (вывод в п.1); `additionalProperties: false`
   на верхнем уровне и на элементе (запрет лишних полей — экономия токенов у стены,
   чистота артефакта). Новый sha256 схемы фиксируется в артефакте.
2. **Гвард 3 (mal), дословно**: mal = число вызовов с parse fail при ЛЮБОМ fr,
   кроме `length`. trunc = число вызовов с `fr=length` (независимо от parse).
   Отдельно считается `other_fail` (exception/unknown-фреймы) — ожидается 0.
   Все фейлы покрыты, дырок нет.
3. **Оговорка для capped/trunc (вместо «структурно»)**: trunc=0 и capped=0
   ОЖИДАЮТСЯ при b2-распределении длин фактов (измерено, п.1); если capped-вопрос
   или fr=length появляется — это флаг «**length-bounding недостаточен**»
   (→ мини-зонд полноты, кандидат — линия Б), а НЕ «нейтральность сломана».
   Красным нейтральности остаются mal>0, other_fail>0, R@5/empty-гварды.
4. **Новые гварды (калибровка + smoke C)**:
   - **loop = 0**: ни одного фрейма с `facts ≥ 2 × unique_texts` (п.2);
   - **facts_at_maxlen = 0**: ни одного факта длиной ровно 900 (trunc-field).
   Любой > 0 → СТОП, таблица осадка совету (классы: grammar-induced loop /
   trunc-field), без ретраев.
5. **Флаги состава — зеркало вверх**: к «g1=0 при b2>0» и «g1 < 50% b2» добавлено
   «**g1 > 120% b2 → review**» (грамматика закрывает salvage-потери b2 → рост правдоподобен
   механически). Обоснование порога 50% (снизу): межпрогонный шум на свежих сторах —
   ±1–2 факта (зонд/b4), потеря >50% состава шумом быть не может — структурный сдвиг.
6. **Опечатка §5**: `1182229` → `118b2229` (сверено с артефактом b4).
7. **Пре-регистрация интерпретации R@5 = 153/156** (ровно −1): если единственный
   промах не из empty/B6-класса — к разбору прикладывается ре-ран b2-конфига
   с `--seed 42` (сравнительный режим Q4) для разделения шум/дельта. Гвард остаётся
   красным до решения совета; послаблений нет.

## 4. Что НЕ меняется

- Конфиг b2 (cap 2000, без B6), слайс/порядок/метрика, seed 42 за веткой;
- гварды 1–2 (R@5 ≥ 0.987, empty ≤ 2) и ядро decision rule;
- прогнозы базового пререга (R@5 [0.980, 0.994], empty 0–1, время ≤ 80 мин) —
  дополняются, не переписываются: **capped 0–3** (31 < b2-натурального максимума 39 →
  39+-класс режется флагом), **loop 0–2 фрейма**, **facts_at_900 = 0**;
- эстафета (ii)→Б переносится в §5 базового пререга дословно (рецензия):

> если (ii) даёт R@5 ≥ 0.987, но стеновые вопросы остаются с fr=length — линия Б
> стартует следующим пакетом немедленно, не «когда-нибудь».
