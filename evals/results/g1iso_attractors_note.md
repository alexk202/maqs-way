## Результат

- Внутри инстанса A: **9/9 байт-идентичны** (аттракторы 7/7).
- Внутри инстанса B: **9/9** (аттракторы 7/7).
- **Кросс-инстанс A↔B: 9/9** (raw/stored/frames; `g1iso_attractors_crosscheck.json`).
- Против инстанса g1-iso-b: stored 9/9.

**Аттракторные вопросы полностью воспроизводимы байт-в-байт при фиксированном
промпте — внутри и между перезапусками сервера.** «Единственное место, где живёт
разброс» при контролируемом промпте разброса не содержит.

## Тогда откуда дрейф классов g1 → g1-iso-a (capped 2→7, loop 2→6)?

Трёхсторонний анализ per-question facts (артефакт crosscheck):

- g1 ↔ g1-iso-a (оба с per-run хвостом): совпадение **125/156**;
- g1-iso-a ↔ g1-iso-b (хвост vs изоляция): **20/156**;
- g1 ↔ g1-iso-b: **21/156**.

Чтение: (1) **хвост глобально перестраивал extraction** — с хвостом vs без
него различается ~135/156 вопросов по составу фактов (хвост не «краевой шум»,
а второй источник контента в промпте: ~250 чужих фактов + сдвиг собственных);
(2) два хвостовых прогона различаются в 31/156 позиций — **состав хвостов-10
различался** (q0 у изолированного temp-стора был пуст против чужой сессии у
живого db; в остальных позициях — тай-брейк выбора 10 строк из N при равных
created_at зависит от физического состояния базы; точные различия невосстановимы
post factum — строки вытеснены). Дрейф capped/loop между g1 и g1-iso-a — это
**детерминированная модель при РАЗНЫХ промптах**, без всякой GPU-недетерминизма.
