# СТОП g1-iso по §1 пререга: «изоляция» уровня прогона не изолирует внутри-прогонный хвост (2026-10-25)

Прогон g1-iso (`run_single156_g1iso.py`, 13:10–14:07 UTC+3, ~57 мин, гард GREEN,
exit 0) механически завершён, но **первичная проверка фикса (§1) дала вне-допуска:
278/1684 = 16.5% confirmed чужих фактов в 87/156 вопросах** — та же доля, что у
замороженного g1 (274/1680 = 16.3%). По пререгу §1 — СТОП до любых других выводов;
шаги §5 после проверки (verbatim-панель §3.3, панель-12×2 §4) НЕ исполнялись.

## Корневая причина (найдена и подтверждена физически)

`temp_history_db(STORE)` — **один history.db на весь прогон**: внутри прогона
`get_last_messages` по-прежнему отдаёт вопросу k хвост-10 сессии вопроса k-1
(механизм `save_messages`-eviction не изменился, merely переехал в temp). Мой
редирект в `ffb5879` ЧИНЯЩИЙ живой стор (H5) ЯВНО сохранял внутрипрогонную
последовательность («within-run sequencing preserved» — так и записано) — но для
цели «изолированный re-measurement» это неверная гранулярность. Формулировка ТЗ
«history_db_path = temp **per store**» означает per-question стор, не per-run.

Доказательства:
1. **Физика**: `mem0single156g1iso_*/history.db` (temp) содержит residue-10 —
   сообщения ПОСЛЕДНЕГО вопроса прогона (q155, сессия о карамели/выпечке) —
   скользящий хвост работал в прогоне.
2. **Внутренний контроль**: вопрос позиции 0 (единственный, чей extraction шёл
   против ПУСТОЙ temp-history) — **0 confirmed утечек**; вопрос позиции 6 несёт
   факты дословно из хейстака вопроса позиции 5 (его предшественника).
3. **Детектор ВАЛИДИРОВАН**: задуманный «негативный контроль» обернулся
   позитивным — хиты на g1-iso настоящие (тот же механизм), не ложные
   срабатывания. Оценка форензики 1b для замороженного g1 (16.3%) ПОДТВЕРЖДЕНА
   как подлинная (за вычетом 0 FP-бюджета: на真正 изолированном вопросе — 0).

## Побочное наблюдение (для §4 и будущих интерпретаций)

При почти идентичных промптах (отличие только у q0: пустой хвост вместо чужого)
классы заметно дрейфуют: **capped 2→7, loop 2→6, facts_at_900 3→0, links_used
165→248; R@5 1.000, empty 0, mal 0, total memories 1684 (база 1680)**. Это
межпрогонная дисперсия классов при пиновом seed — прямая_inputs для части B
(ожидать «GPU-недетерминизм остаётся» как реалистичный исход) и для любых
loop/capped-гвардов будущих пререгов.

## Следствия и решение за владельцем

1. **g1-iso как прогон НЕ является изолированным re-measurement'ом** (изолирован
   только q0); его вердикты по §2/§3 пререга не выносятся.
2. **Настоящая изоляция требует per-question history**: в cfg раннера
   `"history_db_path": temp_history_db(f"{STORE}/q{qi}")` — однострочная дельта
   `run_single156_g1iso.py`. Вопрос к владельцу: (a) санкционировать повтор
   g1-iso с per-question изоляцией (порядок §5 заново с шага 3); (b) решить
   гранулярность для ВСЕХ раннеров (per-question — истинная H5-изоляция, но
   меняет семантику future runs: внутрипрогонная история исчезает совсем —
   поскольку отдельные вопросы всё равно не связаны, семантической потери для
   метрик нет, раскрытие записано).
3. `:8085` НЕ выгружен (прогон может быть повторён по санкции; п.5 ТЗ — после
   финального прогона).

## Решение владельца (2026-10-25, после СТОПа): g1-iso-a = replicate of frozen g1

Остановленный прогон сохранён как есть и переименован по смыслу:
**«g1-iso-a (per-run isolation) = replicate of frozen g1»** — второй замер ТОЙ ЖЕ
конфигурации (per-run history-хвост внутри прогона сохранялся, как у замороженного
g1; единственное отличие — q0 шёл против пустого хвоста вместо хвоста b4). Прогоны
g1 (24.10) и g1-iso-a (25.10) — пара «одна конфигурация, два замера» для оценки
межпрогонного разброса классов при T=0, seed 42.

### Межпрогонный разброс классов: g1 vs g1-iso-a

| метрика | g1 (заморожено, 24.10) | g1-iso-a (replicate, 25.10) | разброс |
|---|---|---|---|
| R@5 evidence | 1.000 (156/156) | 1.000 (156/156) | стабильно |
| empty / mal / other_fail / trunc | 0 / 0 / 0 / 0 | 0 / 0 / 0 / 0 | стабильно |
| calls wrapped / finish_reasons | 156 / stop×156 | 156 / stop×156 | стабильно |
| total memories | 1680 | 1684 | +0.2% — стабильно |
| **capped (facts==31)** | **2** | **7** | **×3.5** |
| **loop (facts ≥ 2×unique)** | **2** | **6** | **×3** |
| facts_at_900 (trunc-field) | 3 | 0 | 3→0 |
| links_used total | 165 | 248 | +50% |
| composition flags vs b2 | 28 | 31 | +3 |
| чужие факты (детектор §1) | 274 confirmed (16.3%), 89 вопр. | 278 (16.5%), 87 вопр. | стабильно (механизм тот же) |

Чтение (для пререгов и гвардов): при пиновом seed стабильны R@5, empty/mal/trunc,
total memories и доля хвостовых фактов; **классы loop/capped/links/facts_at_900
дрейфуют в разы между прогонами одной конфигурации** — пороги этих классов в
одиночных прогонах не интерпретируемы без полос по повторам (прямой вход в
правило amend-1: расхождение повторов части B → «полосы по N повторам»).

## Amend-1 (решение владельца п.2–3, к исполнению)

1. Изоляция **per-question** во всех раннерах:
   `history_db_path = temp_history_db(f"{STORE}/q{qi}")` (эквивалент для проб);
   раскрытие в коммите; H5-гард без изменений.
2. Порядок по amend-1: сначала часть B (панель-12×2, байт-идентичность, ~12 мин),
   затем g1-iso-b (~1 ч). §1 (чужие факты = 0) — первичная проверка для ОБОИХ
   шагов. Новое правило: расхождение повторов части B → классовое сравнение
   g1-iso-b против g1 по одному прогону не интерпретируется; вместо этого —
   предложение пакета «полосы по N повторам» владельцу.
