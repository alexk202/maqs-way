## 1. Схема (канон g1 после amend-1; sha256 канонизирован в артефакте)

```json
{"type": "object", "additionalProperties": false,
 "properties": {"memory": {"type": "array", "maxItems": 31, "items": {
   "type": "object", "additionalProperties": false,
   "properties": {"id": {"type": "string"},
                  "text": {"type": "string", "maxLength": 900},
                  "linked_memory_ids": {"type": "array", "items": {"type": "string"}, "maxItems": 10}},
   "required": ["id", "text"]}}},
 "required": ["memory"]}
```

- Форма = ровно то, что парсит mem0 (`json.loads(...).get("memory", [])`, элемент `.get("text")`;
  примеры в ADDITIVE_EXTRACTION_PROMPT: `{"memory": [{"id": "0", "text": "…", "linked_memory_ids": […]}]}`).
- **maxItems = 31** (length-bounding; вывод amend-1 §1, все входы измеренные):
  `floor(1800 токенов × 4.0 chars/токен ÷ (190 + 40)) = 31`, где 1800 = 2000 × 0.9.
  Диапазон совета (25–32) брондирует значение. Хвост выше p90 может приближаться к
  стене — покрывается оговоркой гварда 4 (capped/fr=length = флаг «length-bounding
  недостаточен», НЕ «нейтральность сломана»).
- **maxLength(text) = 900**: измеренный максимум факта 435 chars, стандарт промпта
  ~700 chars → запас 1.29×; снижение потолка режет легитимные детальные факты.
- **additionalProperties: false** (amend-1 п.3.1): запрет лишних полей — экономия
  токенов у стены, чистота артефакта; mem0 читает только `memory` → безопасно.
- Пустой массив разрешён (кейс «нечего извлекать», пример 3 промпта).
- `linked_memory_ids` НЕ обязателен (по промпту: «omit or pass empty array») — обязательность
  не навязываем, использование пишем в метрику (бейзлайн для (ii)).

## 3. Гварды (захардкожены ДО чисел; совет 24.10 §11.1–11.3 + amend-1 п.3)

1. **R@5 ≥ 0.987** (уровень b2, 154/156) — нейтральность.
   Пре-регистрированная интерпретация (amend-1 п.3.7): при ровно 153/156 и промахе
   вне empty/B6-класса — к разбору прикладывается ре-ран b2-конфига с `--seed 42`;
   гвард остаётся красным до решения совета.
2. **empty ≤ 2** (уровень b2).
3. **mal = 0** (amend-1 п.3.2, дословно): вызовов с parse fail при ЛЮБОМ fr, кроме
   `length`, — ноль. Грамм-слой обязан закрыть mal-класс структурно.
   Дополнительно `other_fail = 0`: ни одного exception/unknown-фрейма.
4. **trunc = 0 / capped = 0** (двойной гвард, совет §11.2; оговорка amend-1 п.3.3):
   ни одного `fr=length`, ни одного вопроса с facts == 31. Ожидается при b2-распределении
   длин (измерено §0); если появляется — это флаг «**length-bounding недостаточен**»
   (→ мини-зонд полноты, кандидат — линия Б), а НЕ «нейтральность сломана». Для
   гвардов 1–2 и mal/other_fail красный остаётся красным.
5. **capped** (facts == 31): флаг полноты, НЕ «успех»: помечается, в (ii) не идёт без
   мини-зонда полноты (expected N → found M против b2-числа вопроса).
6. **loop = 0** (amend-1 §2): ни одного фрейма с `facts ≥ 2 × unique_texts`
   (калибровкой вскрыт grammar-induced loop с дедуп-коллапсом состава).
7. **facts_at_maxlen = 0**: ни одного факта длиной ровно 900 (trunc-field, smoke C).
8. **Состав памяти (совет §11.3; зеркало amend-1 п.3.5)**: по-вопросный отчёт
   Δmemories против b2-артефакта; флаги на review: g1=0 при b2>0, g1 < 50% b2,
   **g1 > 120% b2** (рост правдоподобен — грамматика закрывает salvage-потери b2).
   Обоснование порога 50%: межпрогонный шум свежих сторов ±1–2 факта (зонд/b4) —
   потеря >50% состава шумом быть не может. Структурная проверка полей (все
   сохранённые тексты непустые); `linked_memory_ids`-usage — в артефакт (бейзлайн (ii)).
