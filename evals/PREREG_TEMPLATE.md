# Шаблон пререга (PREREG_TEMPLATE.md, v1.1 — v1 + обязательное поле «состав
# популяции прогона» по разбору Совета 26.10: эффекты, измеренные на
# подвыборке, не масштабируются пропорционально доле подвыборки, если
# популяции структурно различаются — прогноз обязан видеть состав)

Обязательная структура для будущих пререгов ветки (включая prereg-lite).
Прешедшие пререги не переписываются; шаблон применяется к новым.

## 0. Статус и дисциплина

- Статус-строка: DRAFT → рецензия → **подпись владельца** → коммит (хеш) →
  прогон. Пререг коммитится ДО любых прогонов пакета.
- Замороженные числа/вердикты не переписываются; всё новое — append-only.

## 1. Дельты

- Ровно перечисленные намеренные дельты к базовой конфигурации (по образцу
  J5: «дельта ровно одна» — или явный список, если санкционировано больше).
- Таблица неизбежных дельт стенда с оценкой влияния — обязательна, если
  базовая линия старше текущего стенда.

## 2. CONFIG-ASSERT (обязательный блок; вводится после аудита mal-гейта)

**Правило: гейты выводятся из ФАКТИЧЕСКОГО конфига прогона.** Пререг не
«верит», что раннер бежит в конфиге X — он ссылается на отпечаток конфига,
который раннер обязан напечатать и захешировать.

- Раннер при старте:
  1. строит канонический JSON фактического конфига (эффективный mem0 cfg:
     llm/embedder/vector_store/history_db_path/version + server-параметры:
     ctx, seed, temperature, max_tokens, response_format, repeat_penalty,
     модель+md5);
  2. печатает `CONFIG_SHA256 = <hash>` первой строкой и вкладывает хеш
     (и сам канонический конфиг) в provenance артефакта;
  3. опционально (первый раннер пакета): сверяет с `EXPECTED_CONFIG_SHA256`
     из env — несовпадение → отказ запускаться (exit 2).
- Пререг: блок «Конфиг» содержит ОЖИДАЕМЫЙ отпечаток (или обязательство
  зафиксировать хеш коммитом пререга до запуска) и таблицу гейтов, у каждой
  строки — **источник базы** (какой прогон/какой конфиг её калибровал).
- **Несовпадение хеша → прогон не запускать** (владелец решает: amend или
  новый пререг).

Справочник конфигозависимых классов (из аудита full-500-iso):

| класс | грамматико-конфиг (json_schema, strict) | json_object-конфиг |
|---|---|---|
| mal (parse-fail@not-length) | структурно ≈ 0 (принуждение) | шумовой класс (b2-эра: ~5% вызовов); гейт «0» недостижим по построению |
| length-стены | кап 2000 + схема: редки | кап 1200 без принуждения: структурны (наблюдалось 5.6%) |
| capped / loop / facts_at_900 | определены схемой (maxItems/maxLength) | не определены (классы бессмысленны без схемы) |
| урожай фактов (total) | один режим extraction | другой режим; переносы между конфигами запрещены |

## 3. Гейты (таблица, обязательные колонки)

| метрика | база | источник базы (конфиг/прогон) | гейт | **строгость** | вердикт |
|---|---|---|---|---|---|

- **Строгость неравенств явная**: `≤` или `<` (и `≥`/`>`), без «около».
- Пограничный результат (ровно на границе) — **отдельный предсказанный
  статус заранее**: «граница = PASS с риск-флагом» или «граница = FAIL»;
  пост-фактум споры запрещены.
- Гейт без источника базы в фактическом конфиге прогона — невалиден по
  построению (см. §2).

## 4. Предсказания агента (ex ante)

- **Состав популяции прогона (обязательное поле, v1.1)**: доля каждого
  структурного класса в выборке (для LongMemEval — доля single-session и
  multi-session вопросов; для иных доменов — аналогичная структурная
  декомпозиция). Прогнозы и гейты, переносящие эффекты с другой
  популяции, обязаны явно оценивать разбавление по этому составу
  (урок full-500-iso: single-156 −13% → full-500 −0.9%, т.к. single —
  меньшинство и хвост разбавлен мультисессиями).
- Диапазоны до прогона; промах прогноза ≠ провал прогона — но раскрывается
  с механизмом (по образцу full-500-iso: population-mismatch и
  config-mismatch называются).
- Экстраполяции между масштабами прогонов (single → full и т.п.) — только с
  оговоркой о разбавлении; перенос эффекта между конфигами запрещён.

## 5. Правило решения (заранее)

- Внутри полос → последствия (что НЕ делаем: перепрогоны/аннотации).
- Вне полос → последствия (пакет к владельцу / finding / СТОП — с явным
  различием «finding, не СТОП» и «СТОП»).
- Красный H5-гард → прогон недействителен.

## 6. Контроль

- Контрольные панели/мини-контроль — по proposal
  `determinism-paired-per-question` (окно, канарейка режима — метка).
- Чеклист стенда (OS, драйвер, сборка, хеши раннеров, md5 модели) — в
  артефакт.

## 7. Порядок и артефакты

- Пронумерованный порядок исполнения; артефакты с именами файлов; сырые
  дампы — в артефакты; выводы — append-only.
