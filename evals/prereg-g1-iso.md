## 1. ПЕРВИЧНАЯ проверка фикса: детектор чужих фактов на сторах g1-iso (поправка владельца п.1)

Тем же шингл-детектором, что измерил утечки (уникальные 5-словные шинглы
датасета; confirmed = ≥2 уникальных шингла ДРУГОГО вопроса; weak = 1;
`history_confound_forensics.py` механика, запуск `g1iso_fix_check.py` на копиях
сторов g1-iso, атрибуция по порядку 156):

- **Ожидание: confirmed = 0.**
- **Допуск (заранее, из ручной верификации хитов на замороженном g1: там 5/5
  проверенных хитов были настоящими, совпадения по ≥2 уникальным шинглам —
  не случайный класс): confirmed ≤ 5 фактов (≤0.35% фактов) в ≤ 5 вопросах;
  weak ≤ 20.**
- **Одновременно негативный контроль детектора**: хиты на g1-iso — его ложные
  срабатывания. FP-rate r = confirmed_iso / n_facts_iso; **поправленная оценка
  замороженного g1 = 16.3% − r** (274/1680 = 16.31%; при confirmed_iso ≤ 5 →
  r ≤ 0.3% → оценка остаётся 16.0–16.3%). Оба числа (сырое и поправленное)
  пишутся в артефакт.
- Вердикт: confirmed в допуске → **фикс подтверждён** (изоляция работает),
  детектор откалиброван; вне допуска → СТОП, разбор до любых других выводов
  (либо утечка, либо детектор/гард ловят непредвиденное — finding владельцу).

движение в обе стороны.

## 3. Правило решения — по затронутым метрикам, пороги заранее (поправка владельца п.2)

**3.1 R@5:** вне полосы ±0.02 → **R@5 < 0.980** → пакет **full-500-iso** к
владельцу (полный изолированный re-measurement линии; его пререг — отдельно
после санкции).

**3.2 Композиция (любое из → заметный сдвиг классов → пакет full-500-iso):**
- total memories вне **[1400, 1800]** (база 1680; прогнозная полоса 1450–1750,
  порог решения шире прогноза);
- loop ≥ **5** вопросов (база 2); capped ≥ **5** (база 2); trunc ≥ **2** (база 0);
- empty ≥ **3** (база 0); mal ≥ **1** (база 0).

**3.3 Verbatim v1.2 на замороженной панели-12 (метрика линии (ii)):** считается
`g1iso_verbatim_panel.py` (import классификатора/экстрактора из замороженного
`verbatim_v12.py`, N1–N8 без изменений) на сторах g1-iso; панель —
замороженные 12 полных id из `verbatim_g1_v12.json` (pair_panel_stratified);
базы — замороженные per-question recall из того же артефакта; **панельная база
(mean) = 0.162** (зафиксирована в `prereg-ii.md` §1).

- **Порог заранее: |panel_mean_iso − 0.162| > 0.03** (~19% базы; больше
  наблюдавшегося калибровочного шума v1.1→v1.2) → **вердикт (ii) АННОТИРУЕТСЯ**
  «measured under confound, re-run pending» (НЕ переписывается) и пакет
  **(ii)-iso идёт к владельцу**.
- Внутри порога → вердикт (ii) аннотируется «baseline within tolerance»
  (confound метрику не сдвинул); аннотация — append-only в
  `history_confound_disclosure_note.md`.

Внутри всех порогов (R@5, композиция, верbatim) → **full-500 НЕ перепрогоняем**,
только аннотация. Любой красный H5-гард / краш сервера → прогон недействителен,
повтор после восстановления стенда (разрыв > 30 мин фиксируется в артефакте).

## 4. Часть B: панель-12 × 2 — гипотеза «разброс = хвост истории, не GPU» (поправка п.3)

Замороженная панель (12 полных id, `verbatim_g1_v12.json`): `75832dbd, 0a34ad58,
1faac195, b0479f84 / fca70973, 311778f1, afdc33df, 19b5f2b3 / e47becba, 58bf7951,
3b6f954b, faba32e5`. Прогон: `run_g1iso_panel12.py` — конфиг g1-iso (дельта §0),
каждый вопрос свежий стор, **два повтора подряд**, seed 42 пинован; сырые ответы
extraction пишутся в артефакт.

**Сравнение — повтор 1 против повтора 2 (оба изолированные), НЕ против
замороженных прогонов.** Критерий (заранее): extraction-выходы байт-идентичны
между повторами (raw content покадрово; эквиваленты: отсортированные
stored-тексты, frames) → хвост истории был источником межпрогонного разброса
(по крайней мере при пиновом seed); различаются → GPU-недетерминизм остаётся.
Граница вывода: ранняя эпоха без пина seed этим критерием не объясняется —
записать дословно. Прогноз агента: 8–12/12 идентичны; расхождения, если будут —
в loop/стеновом классе. Доля идентичных и профиль расхождений — в артефакт
независимо от вердикта.
